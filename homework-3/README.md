### Что было в базовом проекте
- Список персонажей и экран деталей
- Навигация между экранами
- Запросы к внешнему API
- Локальное хранение (Room) и реактивное обновление UI

### Что добавлено в финальной работе
#### 1. Offline-first кэш персонажей (Room)
  - UI строится на основе локального кэша: даже без сети можно просматривать ранее загруженных персонажей
  - Сеть используется для обновления кэша и синхронизации, а не как единственный источник данных
#### 2. Политика актуальности данных (TTL) и управление ей пользователем (Settings + DataStore)
  - В настройках можно выбрать свежесть кэша (TTL)
  - TTL влияет на то, когда приложению нужно обновлять локальные данные из сети
#### 3. История просмотров (Recent) как пользовательские данные (Room)
  - При открытии деталей персонаж сохраняется в историю
  - Есть отдельный экран Recent со списком последних просмотров
  - Пользователь может очистить историю
  - Размер истории ограничен
#### 4. Фоновое обновление через WorkManager
  - В настройках можно включить/выключить фоновое обновление, выбрать “Wi Fi only” и интервал
  - В фоне приложение синхронизирует данные по персонажам, важным для пользователя (избранное и последние просмотренные)
  - В настройках отображается время последнего успешного фонового обновления

### Новые пользовательские данные (локальная модель)
- Recent views: история просмотров персонажей (Room)
- Cached characters: кэш персонажей с временем обновления (Room)
- Настройки приложения: тема, TTL кэша, параметры фонового обновления, время последнего успеха (DataStore)

### Ключевые пользовательские сценарии
- Просмотр списка и деталей с оффлайн поддержкой (данные берутся из кэша, сеть обновляет)
- Управление свежестью данных через TTL в настройках 
- Просмотр и управление историей Recent (автодобавление, экран истории, очистка)
- Фоновая синхронизация данных по интересующим персонажам (favorites + recent) с настройками интервала/сети

### Технологии
- UI: Jetpack Compose, Navigation Compose
- DI: Hilt
- Network: Retrofit + OkHttp logging
- Local storage: Room
- Preferences/Settings: DataStore (Preferences)
- Background: WorkManager
- Async/Reactive: Kotlin Coroutines + Flow

### Тесты
- Unit-тесты на оффлайн/реактивную логику и планирование фоновых задач
- Instrumentation тесты для Room DAO (история Recent)

### Как проверить offline-first
1.	Один раз открыть приложение с интернетом и загрузить список/деталку.
2.	Выключить интернет.
3.	Повторно открыть приложение: ранее загруженные данные отображаются из локального кэша.
4.	Проверить экран Recent: история доступна оффлайн.
